# B2: dataLayer observer (MAIN world)
Type: capture
Size: M

## Goal
Show what the site *pushed* to `window.dataLayer` next to what was *sent* on the network, so "pushed but never sent" becomes visible. The pinupgirlwellness case is the motivating example: GA4 loads via GTM but never sends. Did the page push `view_item_list`, `add_to_cart` etc. at all?

## Acceptance criteria
- [ ] A content script runs in the MAIN world (`world: "MAIN"`, `run_at: document_start`) only on tabs that are being recorded. It doesn't run on unrecorded tabs.
- [ ] It wraps `dataLayer.push` (including a dataLayer created after the script runs and a renamed one from `gtm.js?l=…`) without changing what the page's push returns or throws.
- [ ] Each push is stored with the session as a `datalayer` record. Fields: time, event name (`event` key, or the gtag command `event`/`config`/`consent` with its first argument), and a redacted copy of the payload (use the existing redaction, never store raw PII).
- [ ] The session log shows the pushes in their own tab or filter, with "sent" or "not sent" against each GA4 event pushed, matched by event name within the same page load.
- [ ] Unit tests cover: push wrapping (array and gtag `arguments`), late dataLayer creation, redaction, and pushed↔sent matching.
- [ ] `npm run e2e` gets a check. Use a site page that pushes an event to the dataLayer which GA4 never sends, and assert it shows as "not sent".
- [ ] `npm run typecheck && npm test && npm run build && npm run e2e` all pass.

## Out of scope
- Feeding the pushes into the LLM audit (separate card).
- Other vendors' data layers (`utag_data`, `digitalData`).

## Notes
- `manifest.json` will need `"scripting"` (already present) and the MAIN-world script registered dynamically with `chrome.scripting.registerContentScripts` when recording starts.
- Keep the observer self-contained (no imports at runtime), like `extension/src/content/pageContext.ts`.
