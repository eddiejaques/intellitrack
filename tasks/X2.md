# X2: Consent issues flagged first, live and in the report
Type: feature
Size: S

## Goal
Consent problems are legal risk, not hygiene, so the user should see them the moment they happen while browsing, and first in the audit. Today they're only found by the rules at audit time (`consentRule`) and sorted with everything else by severity.

## Acceptance criteria
- [ ] Live: while recording, the side panel and session log show a consent warning as soon as it's detectable. It names the hits and links to them in the log. It covers:
  - a GA4 or Google Ads hit with no consent signals (`gcs`/`gcd` missing);
  - a hit sent before any consent default was set;
  - analytics or ads storage granted on a hit while a consent banner (CMP) is still showing and unanswered, if X1's banner detection is available. Otherwise skip this case.
  - user_id sent while analytics consent is denied.
- [ ] The checks are a pure function over the session's events, shared by the live view and the rules (no duplicated logic in `rules/universal.ts`), with unit tests for each case and for a clean session (no warning).
- [ ] Report: consent findings (rule and LLM, category `consent`) are always listed first, in their own "Consent" group, whatever their severity relative to other findings.
- [ ] Audit prompt: the LLM is told to check consent first and to report every consent problem it can see, even "low" ones.
- [ ] The local test site gets a page that fires a GA4 hit without consent signals, and `npm run e2e` checks that the live warning appears.
- [ ] `npm run typecheck && npm test && npm run build && npm run e2e` pass, and `npm run eval -- --mock` still passes.

## Out of scope
- Blocking or changing the site's tags.
- Non-Google consent frameworks (TCF strings) beyond detecting that a CMP is present.

## Notes
- Rules: `extension/src/rules/universal.ts` (`consentRule`, `gcsFlags`).
- Live warnings: follow the silent-GA4 pattern in `extension/src/ui/logview.ts` (around `silentGa4`) and `extension/src/ui/panel.ts`.
- Report grouping: `extension/src/ui/report.ts`.
