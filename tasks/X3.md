# X3: Short findings: problem, severity, fix
Type: ui
Size: S

## Goal
The report is too wordy. Each finding should read at a glance as **problem · severity · how to fix**, and the detail should only be there if you open it.

## Acceptance criteria
- [ ] Every finding (rule and LLM) shows three things by default:
  - a severity chip;
  - the problem in one line, ≤ 90 characters;
  - the fix in one line, ≤ 120 characters.
  Evidence IDs, the longer explanation and the LLM's review of rule findings move into a collapsed "Details" disclosure.
- [ ] LLM output schema (`AUDIT_SCHEMA` in `extension/src/shared/schemas.ts`):
  - `title` gets `maxLength` 90 and `recommendation` gets 120;
  - `detail` becomes optional with `maxLength` 300;
  - `rule_reviews[].explanation` gets `maxLength` 160.
  Existing schema tests are updated, and an over-long answer still goes through the one retry, then a clean failure.
- [ ] Audit prompt (`shared/prompts/audit_v1.md`) is rewritten shorter:
  - the output style is "problem in one sentence, fix as one imperative sentence, no preamble";
  - the headline stays one sentence;
  - the prompt itself ends up no longer than it is today.
- [ ] Rule texts in `extension/src/rules/*.ts` are shortened to the same format: titles ≤ 90 characters, recommendations ≤ 120. A unit test enforces the limits for every rule's output on the fixtures.
- [ ] The report's summary shows counts by severity above the list (e.g. "2 critical · 3 high · 1 medium").
- [ ] The report works in light and dark and at 380 px width. Screenshots of `report.html` (light and dark) are attached to the review note.
- [ ] `npm run typecheck && npm test && npm run build && npm run e2e` pass, and `npm run eval -- --mock` still passes.
