# X4: Mandatory deep task description gate
Type: process
Size: S

## Goal
Every task the dev agent builds should start from a full written description in `tasks/<ID>.md`, not from a one-line backlog row. That way the PM can review what will be built before it's built, and the agent blocks less often on unclear scope. Today the only gate is "at least one acceptance criterion" (`hasCriteria` in `scripts/kanban-lib.mjs`). That still lets a thin card through, and the board doesn't show which backlog items have no description yet.

## Acceptance criteria
- [ ] A task description passes the gate only when `tasks/<ID>.md` has all of these, each non-empty and not the template placeholder:
  - `# <ID>: <title>` heading, with `Type:` and `Size:` lines;
  - `## Goal`: at least 150 characters: who it's for, the problem, why now;
  - `## Acceptance criteria`: at least 3 real `- [ ]` items, the last one naming the checks (`npm run typecheck && npm test && npm run build`, plus `e2e`/`eval` where relevant);
  - `## Out of scope`: at least 1 item;
  - `## Notes`: names at least 1 repo file path that exists (`extension/…`, `scripts/…`, `shared/…`, `tests/…`);
  - `## Dependencies`: card IDs that must be done first, or "none".
- [ ] The gate is one pure function in `scripts/kanban-lib.mjs` (`checkSpec(text, { fileExists })`). It returns the list of what's missing, and is unit-tested for each rule plus a passing card.
- [ ] `npm run kanban -- set <ID> ready` refuses a card that fails the gate and prints exactly what's missing. `--force` still overrides, and the board shows a ⚠ on a forced card.
- [ ] `npm run kanban -- set <ID> ready` also refuses a card whose Dependencies aren't `done`. The error names them.
- [ ] `npm run kanban -- lint` lists every card in Backlog, Ready and In progress with its gate status (✓ specified / ✗ what's missing). It exits non-zero if a Ready or In-progress card fails.
- [ ] `kanban.md`:
  - the Backlog table gets a "Spec" column (✓ / ✗ / —, where — means no task file yet);
  - every card ID links to its `tasks/<ID>.md` when that file exists;
  - Ready cards with a failing spec show the ⚠.
- [ ] `npm run kanban -- new` writes the full template, including `## Dependencies`, with guidance in each section.
- [ ] `/development-start` checks `npm run kanban -- lint` for its card before starting it, and blocks the card (4b) with the missing items as its question if the gate fails.
- [ ] `/review-start` lists cards that fail the gate under "Next to refine".
- [ ] The existing cards (B2, X1, X2, X3, B20) pass the gate, after adding their `## Dependencies` sections. That edit to board files is allowed in this card.
- [ ] `docs/dev-workflow.md` and `CLAUDE.md` describe the gate.
- [ ] `npm run typecheck && npm test && npm run build` pass.

## Out of scope
- Writing descriptions for the other backlog items (B3…B25). That's review-mode work ("refine B3").
- An HTML board with side-by-side columns (separate card if wanted).

## Notes
- Gate today: `hasCriteria`, `newTaskTemplate` and `render` in `scripts/kanban-lib.mjs`; the `set` command in `scripts/kanban.mjs`.
- Tests: `tests/kanban.test.ts`.
- Commands: `.claude/commands/development-start.md`, `.claude/commands/review-start.md`.
