# X5: dataLayer in the audit: present or not, and were pushed events sent
Type: rules
Size: M
Depends on: B2

## Goal
The dataLayer is where the site says what happened ("add_to_cart", "purchase"). The vendors' hits are what actually went out. The auditor wants two answers in the report:
1. **Is there a dataLayer at all?** Many sites don't have one (hard-coded gtag, server-side, other tag managers), so absence is reported as a **fact, never as a fault**.
2. **Did each event the page pushed eventually reach a vendor** (GA4 now; Google Ads and later vendors through the same check)? A pushed event that never becomes a hit means the site did its part and the tagging did not.

GTM's own mechanics (container loaded, `gtm.*` lifecycle events, triggers) are not judged. Only the push and the vendor hits count.

B2 only shows sent/not sent in the live log's Data layer tab. Nothing reaches the rules, the audit or the report.

## Acceptance criteria
- [ ] **Presence, per session and per page load.** The report has a "dataLayer" line: *found* (layer name(s), e.g. `dataLayer`, and the number of page loads it was seen on out of all page loads) or *not found*. "Not found" is shown as information with the text "No dataLayer on these pages; push-to-hit checks were skipped". It is never a finding, and it never lowers the score. Unit-tested for: all pages, some pages, none.
- [ ] **Eventually sent.** A pure function (generalising `sentStatus` in `extension/src/shared/datalayer.ts`) matches each event push to vendor hits. A push counts as **sent** when a hit with the same event name, from any captured vendor that maps it, came from the same page load, or from the same tab within 10 s after the push (this covers a redirect right after `purchase`). Vendor mapping:
  - GA4: the event name.
  - Google Ads: `gtag('event','conversion',{send_to:'AW-…/label'})` is matched to an Ads conversion hit with that label.
  - Every other vendor returns "no mapping" for now. That is a hook for B5 and later vendor cards, not a verdict.

  Unit tests cover: same page load; a hit after a redirect within the window; a hit outside the window (not sent); an Ads-only push matched by label; a push with no mapped vendor (no verdict).
- [ ] **No verdict for**: `gtm.*` events, pushes without an `event` key, `config`/`consent`/`set`/`js` commands, and pushes from before recording started (as in B2).
- [ ] **Findings, with noise kept low.** "Not sent" pushes become rule findings (category `missing_event`, evidence = the push IDs):
  - **high** when the event is in the journey plan or is a GA4 recommended event (`purchase`, `add_to_cart`, `begin_checkout`, `generate_lead`, `sign_up`, `login`, … from the existing recommended list);
  - **low**, all grouped into one finding ("N custom dataLayer events were never sent: …"), for everything else. Consent-tool events like `OneTrustGroupsUpdated` land there instead of producing one finding each.
- [ ] Push IDs are in the minimised audit payload (names, page, time and sent status only, no payload values), so the evidence check in `audit.ts` doesn't drop these findings and the LLM can cite pushes. The preview shows them and contains no raw PII.
- [ ] The live log's Data layer tab uses the same function, so the live view and the report never disagree.
- [ ] The local e2e site gets a page **without** a dataLayer that fires a GA4 hit, and `npm run e2e` checks that the report shows "not found" with no dataLayer finding. The existing `never_sent_test` page produces a "not sent" finding in the report.
- [ ] README.md and docs/workflows.md describe the presence line and the findings.
- [ ] `npm run typecheck && npm test && npm run build && npm run e2e` pass, and `npm run eval -- --mock` still passes.

## Out of scope
- Judging GTM itself: whether a container loaded, trigger setup, `gtm.*` events.
- Other tag managers' data layers (Tealium `utag_data`, Adobe `digitalData`). Adobe belongs to B22.
- Comparing push parameter values with hit parameter values (e.g. pushed `value` vs sent `value`). That could be a follow-up card.
- Mappings for vendors that aren't captured yet. Each vendor card adds its own mapping.
